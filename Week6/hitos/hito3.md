# Hito 3: Gestión de datos y escalabilidad (QuickCart - Week 6)

## Planteamiento y Objetivos
Vamos a comprender cómo los datos definen la arquitectura y condicionan la escalabilidad. Para al menos 3 microservicios, definir:
- Quién es dueño de los datos?
- Tipo de persistencia sugerida (SQL / NoSQL / Event Store) -> justificar.
- Cómo escala ese servicio: horizontal / vertical / ambos, justificar.
- Investigar un vendor de base de datos o infraestructura: PostgreSQL, MongoDB, DynamoDB, Redis, etc. Cuál elegirías? (Mismos criterios que el hito anterior, pero ahora agregando la escalabilidad como criterio).
- Identificar un potencial efecto dominó si ese servicio contratado escala mal, y un potencial anti-patrón.

Entregables del hito:
- Tabla simple: Servicio | Datos | Escalado | Riesgo
- Un párrafo sobre un anti-patrón evitado.
- Explicaciones que consideren pertinentes.
